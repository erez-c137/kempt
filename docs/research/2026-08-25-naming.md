# Naming research and shortlist

Date: 2026-08-25. Status: research only. Nothing is renamed by this document - it exists so the
name decision on the roadmap ("v1.x - Name decision") can be made in one sitting.

**Headline:** "Upkeep" is not a neutral placeholder any more. Two other actively maintained
Linux system updaters are already called `upkeep`, and a venture-funded maintenance-software
company owns the word commercially. The first page of "upkeep linux" is entirely other people's
projects. This is the cheapest week this project will ever have to change it: the repo is one
day old, private, zero stars, unpackaged, and the widget plan that would bake `org.erez.upkeep`
into a Plasma plugin Id has not been executed yet.

Recommendation up front: **rename to `Kanso`**, with **`Kempt`** as the close second if a real
English word matters more than a clean namespace. Detail in section 4.

---

### 1.2 Does the SaaS matter for an OSS desktop tool?

Legally, mostly no. Different Nice classes, no consumer confusion between a $24/user/month CMMS
and an MIT-licensed Plasma applet, and nobody sends a cease-and-desist over a GitHub repo in a
different market. Practically, yes - it costs the entire top of the search page. A person who
hears the name at a Fedora meetup and types "upkeep" gets a maintenance-management sales funnel
before it gets anything installable.

### 1.3 The discoverability test

Search "upkeep linux" today and page one is: the Read the Docs for the Gentoo tool, LinuxLinks'
writeup of the Arch TUI, the Gentoo tool's own site, Ubuntu ESM (unrelated), and four results
about the CMMS company. There is no slot on that page for a Fedora/KDE updater called upkeep -
the two slots a Linux updater named upkeep could occupy are already occupied by Linux updaters
named upkeep.

### 1.4 Where Upkeep is genuinely clean

To be fair to the incumbent, the namespaces that matter for shipping are all free:

- Fedora 44 + RPM Fusion: no package named `upkeep` (verified by `dnf5 repoquery`).
- COPR: no project named `upkeep` (verified via the COPR API).
- AUR: `upkeep` is free.
- Debian: no source package `upkeep`.
- KDE Store: **zero** results for "upkeep" (verified via the OCS API, which returns 533 results
  for a control search of "weather", so the zero is real).

So the problem is not "you cannot ship under this name". The problem is "nobody will ever find
it, and two other Linux updaters will be mistaken for it".

## 2. Twelve candidates

Read the CLI column out loud - it is the thing typed a thousand times. The polkit column shows
the id family each name implies; all of them replace `org.erez.upkeep.{refresh,apply}` and the
`upkeep-refresh` / `upkeep-apply` root helpers.

### Cut before screening

- **Cadence** is out on sight: `cadence` is a well-known JACK audio toolkit on Linux (falkTX/Cadence,
  375 stars) packaged for multiple distros, plus cadence-workflow/cadence (9,413 stars) and Cadence
  Design Systems. A Linux tool called cadence already means something else to Linux users.
- **Vigil** and **Evergreen** are out on saturation: valeriansaliou/vigil (1,941 stars, a status-page
  monitor - adjacent domain) and munificent/vigil (3,037 stars); segmentio/evergreen (12,424 stars),
  evergreen-ci (MongoDB's CI system), and Evergreen ILS in library software.
- **Kaizen** is out on genericness: 6,207 GitHub repos, and the word is a consulting buzzword outside
  software. It would never be *this* project's word.
- **Uphold** is out: forward3d/uphold (588 stars, a database-backup verifier) plus Uphold the crypto
  exchange, and the CLI does not read.

That leaves six to screen properly.

## 3. Availability screen: the top six

Method and its limits, stated honestly:

- **GitHub**: `gh api search/repositories` for name matches, then verified the top exact matches
  individually (stars, language, last push, archived flag). GitHub's search is substring-based, so
  raw counts for short words like "tend" are inflated - the exact matches are the real signal.
- **Fedora**: `dnf5 repoquery` against Fedora 44 x86_64 + updates + RPM Fusion on this machine.
  Control-checked against `bash`. This does **not** cover EPEL or Rawhide-only packages.
- **COPR**: the official `api_3/project/search` endpoint, checked for exact project-name matches.
- **AUR / Debian**: AUR RPC v5 `info` (exact name), and sources.debian.org `api/src/<name>`.
  Both included because the roadmap's apt and pacman backends make those namespaces real later.
- **KDE Store**: the OCS API at api.opendesktop.org. **store.kde.org itself is behind Anubis
  anti-bot and could not be fetched**, so the web UI search was not verified by hand - but the OCS
  API is the same catalogue the Plasma "Get New Widgets" dialog queries, and it returned 533 hits
  for a "weather" control search, so its zeroes are trustworthy.
- **Domains**: crude `dig NS` check. NS records present = registered. **No NS does not prove the
  domain is purchasable** - it only means nothing is served from it. Nobody checked a registrar.
- **npm / PyPI / crates.io**: existence check via each registry API. Not directly needed for a bash
  CLI, but a taken registry name is a signal of how contested the word is, and matters if a helper
  is ever published.

### 3.2 Reading the results

- **Kanso** is the only candidate with no live software collision anywhere that matters. Its one
  namesake is a 488-star repo that has been formally archived for seven years, and the general-web
  noise is design blogs, not tools. PyPI is free, the KDE Store is empty, every distro namespace is
  free.
- **Kempt** is clean in every distro namespace but has a real operational wart: a `kempt` binary
  already exists in the wild and is actively maintained. Two `kempt` binaries in `$PATH` is a
  genuine, if rare, conflict - and it is precisely the kind of sloppiness this project's character
  argues against.
- **Trilby** has the cleanest package-registry profile of all six (PyPI and crates.io both free,
  zero COPR projects match even by substring). Its single collision is small in stars but bad in
  placement: ners/trilby is a Fedora-flavoured Linux distribution. "Trilby Fedora" is a search this
  project would lose forever.
- **Keel** dies on semantics, not paperwork. keel-hq/keel automates updates for a living.
- **Brim** dies on the AUR package plus common-word saturation, and says nothing about updating.
- **Tend** has the best CLI ergonomics on the entire list and the worst discoverability. If nobody
  ever has to find this project by searching, Tend wins; since strangers finding it is the whole
  point of going public, it loses.

### 3.3 The naming neighbourhood it would ship into

For calibration, what update widgets are actually called on the KDE Store and GitHub today:
`bs-updater`, `apdatifier` ("KDE Plasma widget that tracks updates for ArchLinux, Plasma Widgets,
Flatpak, and Firmware"), and Discover's own notifier. The bar is low and descriptive-ugly, which
means a real name stands out - and it also means opacity is survivable, because `apdatifier` is
popular and means nothing either. In both cases the store listing carries the keywords, not the
name: list it as "Kanso - System Updates" with the summary doing the searchable work.

## 4. Shortlist and recommendation

### The three

**1. Kanso** - the clean-namespace pick.
Free everywhere that matters: Fedora, COPR, AUR, Debian, KDE Store, PyPI. Its only namesake is
archived since 2018. Five letters, unambiguous to type and to say, no shell-word collision.
`kanso check` / `kanso update` reads short and distinct. The meaning maps exactly onto the
product's actual argument - beauty by subtraction, one icon instead of a wall of output, a badge
that counts only what is actionable. It fits the Fedora and KDE habit of naming tools with
borrowed words (Koji, Bodhi, Kirigami) rather than describing them.
*Cost:* opaque until explained. Someone browsing the KDE Store for "update" will not find "Kanso"
unless the listing title and summary carry the keywords - which they should anyway.

**2. Kempt** - the honest-English pick.
Means "kept tidy" and nothing else. Starts with K, so it lands naturally in a KDE app list without
being a K-gimmick. Free in every distro namespace and the KDE Store. `kempt check` reads plainly.
*Cost:* an actively maintained `kempt` binary already exists (a source formatter), so `$PATH`
conflict is possible; `kempt.md` is a live consumer app being marketed right now; npm, PyPI and
crates.io are all taken; and "Kemp" is a known B2B brand phonetically. None of it is fatal, all of
it is friction that Kanso does not have.

**3. Trilby** - the community-wink pick.
The best package-registry profile of the six and a name Fedora people will smile at. Distinctive,
memorable, unmistakably not a SaaS.
*Cost:* ners/trilby is a NixOS-based distro explicitly modeled after Fedora Linux. Every
"trilby + fedora" search fights that project directly, and it is the exact audience overlap this
name was chosen for. Worth choosing only if that trade is made with eyes open.

*(Fallback outside the three: **Tend**, if CLI feel is worth more than ever being found. It is the
nicest thing to type on the list and the hardest thing in the world to search for.)*

### Recommendation: rename to Kanso, this week

**Keeping "Upkeep" is the worst of the four options, and the reason is not aesthetic.** Two
actively maintained Linux system updaters already carry the exact name - one for Arch, one for
Gentoo, one of them pushed yesterday. Shipping a third means permanent explanation overhead in
every forum post ("not that upkeep, the other one"), a first search page that belongs to other
people, and a real risk that a bug report or a security report lands in the wrong tracker. The
CMMS company is a smaller problem than those two repos, but it removes the last unclaimed slot on
the page.

**And the rename cost is at its all-time floor right now.** Priced honestly:

| Cost item | Reality |
| --- | --- |
| Occurrences in the tree | 1,340 across 39 files, of which ~481 are identifier-shaped (`org.erez.upkeep`, `UPKEEP_*`, `upkeep-refresh`, `upkeep-apply`) |
| Files to rename | 10 (`bin/upkeep`, `libexec/upkeep-{apply,refresh}`, `polkit/org.erez.upkeep.policy`, `polkit/49-upkeep.rules.in`, `docs/man/upkeep.1`, four plan/spec docs) |
| Polkit action ids | 2 (`org.erez.upkeep.refresh`, `org.erez.upkeep.apply`) - not yet deployed anywhere but this workstation, and `install.sh --uninstall` already removes them cleanly |
| Docs | 8 files, all written in the last two days |
| Muscle memory | One person, on a repo **created 2026-08-24** |
| Users, packages, store listings | Zero. Repo is **private**, 0 stars, unpackaged, no KDE Store entry, no COPR |

That is a mechanical `git mv` plus a careful `sed` plus one review pass over `install.sh`, the
polkit policy and the test suite - a couple of hours, and the existing test suite proves it landed.

**The window closes with the widget plan.** `docs/plans/2026-08-25-upkeep-widget.md` bakes
`org.erez.upkeep` into a Plasma plugin `Id` in `plasmoid/metadata.json`, into the
`kpackagetool6 -t Plasma/Applet -i/-u/-r` calls in `install.sh`, and into
`~/.local/share/plasma/plasmoids/org.erez.upkeep`. A plasmoid Id is the one identifier that is
genuinely expensive to change later, because the KDE Store listing, every user's installed package
directory and every panel's saved applet reference all key off it. Renaming before that plan runs
costs a search-and-replace. Renaming after it ships costs a migration.

**One thing to settle at the same time.** The rename touches every reverse-DNS id anyway, so this
is also the moment to decide whether the namespace should stay `org.erez.*`. A personal-name
namespace is fine forever, but if this project ever goes to Flathub or wants a domain-backed id,
the conventional choice for a project without its own domain is `io.github.erez_c137.kanso`.
Deciding it now costs nothing; deciding it after the plasmoid ships costs the same migration as
the name itself.

### What was not verified

- **store.kde.org's web UI search** - blocked by Anubis anti-bot. The OCS API (the same catalogue
  Plasma's own "Get New Widgets" dialog uses) was queried instead and control-checked, but nobody
  eyeballed the store website.
- **Domain purchasability** - the `dig NS` check distinguishes "something is served here" from
  "nothing is served here". A "free?" in the table is a lead, not a confirmation. Check a registrar
  before relying on any of them.
- **Trademark searches** - no USPTO/EUIPO/WIPO search was run for any candidate. For an MIT desktop
  tool this is a low risk, but it is unexamined risk. "Kanso" appears as a brand in interior design
  and wellness, which are unrelated Nice classes, but that is an observation and not a clearance.
- **Fedora EPEL and Rawhide-only packages** - the `dnf5 repoquery` covered Fedora 44 x86_64 plus
  updates plus RPM Fusion as configured on this machine.
